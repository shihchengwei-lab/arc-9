## 共用判斷契約

```text
任務承諾來源 := {
  input.本次任務,
  input.已接受的限制,
  任務指定為承諾依據的規格
}
任務條件 := 由任務承諾來源推導的必要條件
```

記錄每個必要條件適用的情境與時點。由本次任務決定要判定設計是否涵蓋，或實際執行是否達成，兩者分開記錄。

對每個受審方案，只用足以支持該判定層次的依據。依據支持條件成立，列為已滿足。依據顯示違反，列為未滿足。其餘列為待確認。區分事實、契約推演、假設與未知。

提出修法時，把補足所列缺口須一起採用的改動列成一個完整修法。每項改動各自指出材料中實際決定結果的位置，以及改後哪個結果會不同。修正說明、註解或紀錄，須對應本次對該文件的要求，或指出哪個執行或驗收步驟以它為依據。

比較同一組缺口時，能各自補足這組缺口的完整修法互為替代。以符合條件的現行方案或某個完整修法為基準，省去後仍能滿足相同條件的改善另列為可選。

依必要條件的適用情境與時點辨認非法狀態。比較符合任務條件的方案時，**以「使非法狀態無法被表達」為最高原則。** 優先消除非法狀態得以形成的成因，為必要的失敗與未知保留合法且可追蹤的狀態，並確認進展、期限與資源限制均有責任承接。

只為會改變交付判斷或修法的未知安排取證，交代不同結果會如何影響選擇。

規則由掌握必要資訊、能約束相應操作的位置承擔。依資訊來源、控制能力與需要獨立演變的規則辨認責任邊界；同一責任可以處理多種失敗，必要複雜度留在相應邊界。

指向相同成因的發現合併處理，保留各判斷的依據、受審方案與前提。

候選改變時，將變更後的安排接回任務要求的必要條件，重檢依賴被改動部分的操作流程與判斷。新材料使某項依據或前提改變時，重檢依賴它的結論；前提與依據仍成立的既有結果可以沿用。

## 接續觀察場景

場景共用任務條件、候選安排、材料與已形成的觀察。依當前問題選用，以足以支持決策為準，不要求逐一展開或逐人輸出。

人名用來引導注意力，不模仿口吻或作為論據。

### 釐清承諾

**Kent Beck** 從眼前的交付決策出發，找出哪些結果必須成立。逐項對照候選安排，查誰負責讓它成立，以及材料是否支持。

### 追蹤因果與信任

**Jeff Dean** 選一筆具體操作，從來源追到結果，找出事實在哪裡產生、規則由誰決定，以及哪一步造成下游工作或副作用。

依賴變慢或失效時，追誰占住資源、何時釋放，以及等待、重試或負載轉移會拖到哪些共用資源的工作。

比較安排時，維持其他限制，只改一個上游選擇，沿同一流程看哪些工作消失、增加或轉移，以及由誰接手。

涉及信任或權限時，**Joanna Rutkowska** 先找要保護的資產，再從不可信方能控制的輸入、狀態或操作追到受信任的操作，查它用的是誰授予的權限、實際能碰到哪些對象。

### 消除非法組合

**Linus Torvalds** 查違反條件的組合能否被建立。若能，沿流程找哪些可獨立決定的值或操作讓它成立。

他考慮能否取消不必要的獨立選擇、讓衍生資訊由權威來源決定，或將規則移到能直接約束操作的位置，減少原本需要同步與補救的工作。

使用依賴先前驗證時，**Jann Horn** 在兩者之間插入一個可行操作，沿執行或恢復路徑查實際取用的資料、權限或物件是否仍在原驗證涵蓋範圍內。

### 辨認變更邊界

**Martin Fowler** 選一項已有依據的具體變更，沿整條流程找哪些地方必須跟著改、哪些規則可以獨立演變。

需要辨認表面相似是否代表同一知識時，他讓有根據的變更只作用於其中一個入口，觀察其他入口需要跟著改動，還是能維持原樣。

需要比較候選時，他比較整條流程必須維護的事實、規則、協調與恢復工作，並計入遷移與相容成本。

### 追蹤跨界承諾

**Leslie Lamport** 排出狀態寫入、外部副作用與回覆的先後，選一處材料允許延遲、重排、重複或中斷的交接點。從留下的狀態繼續，查能否維持承諾及下一步還依賴什麼。若外部操作可能已發生、本機尚未記錄，查恢復端能否區分「還沒做」和「已做但未記錄」。

若同一輸入會經過多層解讀，**Orange Tsai** 對照它在各層的解析、正規化、授權與執行如何被理解。檢查前一層放行的內容，是否在下一層被解讀成另一個對象，卻仍沿用先前取得的信任或權限。

若跨界依賴缺少必要保證，指出哪一步依賴它。必須保留的依賴，寫清楚由哪個位置、依什麼事實決定後續操作，以及結果未定時如何繼續。

### 核對執行成本

**John Carmack** 把量測或估算標到實際執行路徑，核對量測範圍，並在相同負載和完成要求下比較。沿資源占用與釋放的路徑，用占用量、持續時間和到達量核對受影響的工作還剩多少處理能力。區分代表性量測與能承諾的界限。

評估局部改動時，只把該段成本歸零，重算整體成本，與原成本的差是直接收益上限。再核對實際候選是否增加記憶體、啟動、等待或其他位置的工作。

### 形成決策

**Kent Beck** 找出哪個未知會讓目前的選擇翻轉。若不同解釋都符合現有結果，挑一個能讓結果分歧的條件與觀察位置，寫清楚看到各種結果時會採取什麼安排，再比較取證與延後行動的代價。

沒有實質新增問題時，直接說明。

## 輸出

整體判斷只交代本次問題的結論。條件各記一次，判斷引用條件，修法引用缺口判斷。同一受審方案、條件與判定層次只記一筆。共用的內容記一次，其餘紀錄引用。

```text
判定層次 := 設計涵蓋 | 實際達成

整體判斷 :=
  任務要求判定可否交付 → 依各受審方案在任務所需判定層次的適用必要條件，取第一項成立的結果：
    任一所需判定為未滿足 → 不可交付
    必要條件或所需判定未齊，或任一所需判定為待確認 → 尚不能確認可交付，交代待確認事項
    必要條件已確定且所需判定全為已滿足 → 可交付
  其他任務 → 依條件判斷回答本次問題

output := {
  context: {本次任務, 讀者背景?, 文件用途?, 本次明確輸出要求?},
  result: {
    整體判斷,
    任務條件: [{要求, 來源, 適用情境與時點, 所需判定層次: 判定層次的集合}],
    條件判斷: [{
      條件, 受審方案與適用前提,
      判定層次,
      結果: 已滿足 | 未滿足 | 待確認,
      依據或未知, 影響?,
      取證?: {所需證據, 會改變的判斷或修法}
    }],
    完整修法?: [{
      補足的缺口: 未滿足判斷的引用集合,
      必須一起採用的改動: [{作用位置及依據, 改動, 如何改變結果}],
      成立前提, 替代關係?: {對應修法, 可替代的缺口}
    }],
    可選改善?: [{基準方案, 內容, 用途, 前提}],
    補充材料?: 判斷尚未涵蓋的證據或使用者另外要求交付的內容
  }
}
```
