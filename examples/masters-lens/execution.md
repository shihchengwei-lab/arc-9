# 合併兩組重述：四案執行紀錄

## 日期與受測版本

2026-10-17，四個獨立 subagent 各審查一個 CSV 匯入方案。受測提示詞由 [SKILL.md 快照](skill-snapshot.md) 與本頁雜湊識別；`91840e8` 是修改前的版本庫基準。

本次只合併兩組重述：方案或資訊改變後的重判規則集中在核心原則的證據段；比較條件留在候選方案段，場景承接比較方法。共三處文字變動，其餘原則、場景與輸入輸出契約不變。

四份題目與前版位元組相同。題目中的效能數字與驗證通過紀錄是給定材料，本輪沒有執行案例中的系統實作。

## 派送與設定

題目與受測 skill 固定後才派送。每個代理收到以下要求，只有案例目錄不同：

```text
請讀取 C:\Users\kk789\Desktop\masters-lenses\experiments\deduplicated-principles-four-cases-2026-10-17\<案例>\input.md 與 C:\Users\kk789\Desktop\masters-lenses\experiments\deduplicated-principles-four-cases-2026-10-17\skills\masters-lens\SKILL.md，使用 $masters-lens 回答題目。
```

`<案例>` 為 `csv`、`security`、`overload`、`complete`。四份實際派送訊息保存在 [metadata.json](metadata.json)。派送形式與前版相同，只更換本輪檔案路徑；共通契約由 skill 提供，沒有另附角色、預期解法或前版回答。

使用 `fork_turns=none`，沿用主代理模型與推理設定，未指定覆寫。工具未提供精確模型版本與 seed。每案各執行一次，共四次，不補抽；完整回答照錄，沒有改寫，測後未再調整提示詞。

主代理閱讀原文，比較整體決策、成因與具體安排、責任歸屬及輸出契約，並核對是否逐位大師硬擠問題、完整案是否新增無材料依據的交付阻塞。

## 與前版比較

- CSV 維持不宜直接實作，保留簡化流程、量測、固定受理序號、版本條件寫入與整批資料／完成狀態同交易。本版先談簡化並核對請求時限，未再列出前版的具體驗證順序。兩版均未展開固定工作輸入與同工作鎖定。
- 資安仍推導出跨租戶讀取及匯入，指出資料庫租戶限制無法修補來源授權。前版取消呼叫者指定路徑；本版在實際開檔位置，依工作租戶驗證正規化後目標，要求驗證與讀取同一檔案。這是可成立的替代授權安排，本版保留了路徑輸入的選擇。
- 過載仍否決單純擴容，保留吞吐估算、受理缺口、重送放大負載、容量准入、拒收、冪等重試與期限處置。前版指定工作與待送事件同交易保存、派送者可靠重試；本版只說工作紀錄承接可恢復排程，未展開保存如何接到後續派送。到期轉失敗並釋放容量後，也未再明說原工作不得執行。恢復安排較抽象，到期執行控制屬未展開的實作前提；不能僅由省略確認安排錯誤。約 60 個等待名額有標明是吞吐估算。
- 完整案仍支持依確認範圍交付，將規則連回入口與資料庫的責任，以給定驗證及量測說明理由，沒有新增修改或補驗證要求。

四案主結論維持，沒有逐位大師報告或硬擠問題。這次比較呈現不同候選安排與具體程度；單次輸出差異未確立由兩組條款合併造成。
