# arc-9

[English](README.en.md)

`$arc9` 是手動呼叫的唯讀工程審查 skill。它會沿著實際操作追查問題怎麼發生，說明方案是否需要改動、該改哪裡，以及判斷的依據。

它以「使非法狀態無法被表達」為最高原則：優先改變資料與操作的安排，讓違反需求的狀態無法建立。審查只讀取任務提供或允許讀取的材料，不修改程式、檔案、設定或外部狀態。

## 實際案例

以下是四個 CSV 匯入方案的審查摘要。

| 題目中的方案 | 審查判斷與建議 |
|---|---|
| 每週約兩次、每次最多 500 筆的 CSV 匯入，預留多格式工廠並加入佇列；舊工作可能覆寫修正資料。 | 不宜直接實作。先保留 CSV 解析、匯入服務與資料庫。工作綁定固定內容，客戶更新與完成狀態在同一筆交易提交。先定義「較新」；若依受理順序，由資料庫配發序號，寫入時只允許較新的工作更新。量測耗時後，再決定是否背景執行。 |
| 租戶只能匯入自己的檔案。API 檢查路徑字串的前綴，檔案服務開檔前會化簡路徑。 | `/tenants/A/../B/customers.csv` 能通過 A 的前綴檢查，開檔時卻讀到 B 的檔案；worker 再把 B 的資料匯入 A，讓 A 查詢。取消任意路徑輸入，由可信租戶身分與固定檔名決定來源。 |
| 每秒到達 20 個工作、完成 2 個，要求等待不超過 30 秒；提案只擴大佇列。 | 單純擴容無法滿足等待上限。API 接納時一併檢查並保留容量，超額拒收。工作與待送訊息在同一筆資料庫交易保存，再由補送程序送進佇列。前端追蹤原工作，重試取得同一工作。已接受工作須在 30 秒內啟動或明確失敗。 |
| 5 人內部工具以單一交易匯入 CSV；重送視為新匯入，允許舊檔再次覆寫修正資料。 | 支持交付。完整驗證後才寫入，交易失敗整批回滾，唯一鍵維持客戶唯一性；重送覆寫與同鍵衝突的處理符合已確認的需求。題目提供的耗時、記憶體與滿載拒收紀錄也符合本期需求。 |

[完整題目與回答](examples/masters-lens/README.md)。

## 使用

模型依當前問題選用方法，例如追蹤一筆資料的處理經過、檢查中斷後重試的結果、比對各層如何解讀同一輸入，或核對耗時與資源用量。這些方法以九位大師的名字收錄於 [SKILL.md](dist/skills/arc9/SKILL.md)。

方案改變後，重新檢查受影響的步驟，確認仍符合原本的要求。

安裝後，在目前的任務討論中呼叫：

```text
$arc9 請檢查目前方案有哪些必要改動。
```

明確指定輸出語言時依指定回答；未指定時，跟隨使用者本次請求的主要語言與書寫形式。中文預設 250–400 個正文字元，英文預設 150–250 詞，全文最多三個條列項目，交代判斷、依據，以及影響決策的未知與必要下一步，不寫客套話或開場白。本次任務可指定其他輸出要求；計數與省略條件見 [skill 共通契約](dist/skills/arc9/SKILL.md)。

[中文請求、英文請求與指定語言覆寫的完整回答及執行紀錄](examples/masters-lens/language/README.md)。

## 安裝

[下載 ZIP](dist/arc-9.zip)，解壓縮後將 `arc9` 資料夾放入 Codex 的 skills 目錄。Windows 預設位置為 `C:\Users\<使用者名稱>\.codex\skills\`；已設定 `CODEX_HOME` 時，使用該目錄下的 `skills`。下個回合即可呼叫 `$arc9`。

也可以直接提供 [SKILL.md](dist/skills/arc9/SKILL.md) 的檔案路徑，請模型讀取並使用。
