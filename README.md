# arc-9

[English](README.en.md)

方案看起來能用，仍可能讓舊資料覆蓋修正、讀到別人的檔案，或在中斷重試時出錯。

`$arc9` 是在 Codex 中手動呼叫的審查工具。它沿資料與操作追查問題，指出方案是否符合需求、哪裡必須改，以及原因。方案已符合需求時，也會直接說明。

審查優先尋找能從資料、權限與操作安排上避免錯誤的改法。它只讀取你提供或允許讀取的材料，不修改程式、檔案、設定或其他系統。

## 效果、成本與限制

- **效果**：在 2026-10-22 測試的 10 個方案審查情境中，都判對方案是否符合指定需求，包括需求已變更、問題已修正的情境。
- **成本**：這輪完整審查的等待時間中位數約 3 分 40 秒。對話中的 AI 與獨立審查者合計用量的中位數約 23.9 萬 token；token 是模型處理文字的計量單位，統計包含重複與快取內容。
- **已知限制**：這輪有一題把可選的文字修改列為必做，讓建議多出不必要的工作；另一題重複交代驗證方式，增加閱讀負擔。

[完整驗證報告](tests/reports/arc9-finalized-2026-10-22.md)保留逐項結果、模型設定與用量計算；[語言測試報告](tests/reports/arc9-language-neutral-2026-10-22.md)記錄中文、英文及另行指定繁體中文的結果。

## 代表案例

以下摘要取自本輪四個 CSV 匯入方案的審查回答。[完整題目與回答](examples/masters-lens/finalized-2026-10-22/README.md)

| 題目中的方案 | 審查指出什麼 |
|---|---|
| 少量匯入先加入尚未需要的多格式支援與排隊處理；舊工作還可能覆蓋後來的修正。 | 找出修正會被舊資料覆寫的順序；先確定哪次更新優先，再依實際耗時決定是否需要排隊處理。 |
| 系統檢查有權存取的目錄，開檔時卻可能繞到其他人的目錄。 | 由登入身分決定可讀寫的資料範圍，實際開檔也必須遵守這個範圍。 |
| 每秒收到 20 件工作，只能完成 2 件，卻承諾等待不超過 30 秒。 | 增加排隊容量無法兌現承諾；需要限制接單量，並處理重送與中斷後的工作。 |
| 需求已接受重送覆寫，資料更新與負載驗證也符合要求。 | 判定目前可交付，沒有必須追加的改動。 |

## 開始使用

執行環境須能另外啟動獨立的 AI 審查者（sub-agent）。它負責檢查方案，再由目前對話中的 AI 整理摘要與附錄。

1. [下載 ZIP](dist/arc-9.zip)，解壓縮後將 `arc9` 資料夾放入 Codex 的 skills 目錄。Windows 預設位置為 `C:\Users\<使用者名稱>\.codex\skills\`。若曾用 `CODEX_HOME` 指定其他 Codex 資料目錄，則使用該目錄下的 `skills`。
2. 下個回合，在目前的任務討論中呼叫：

```text
$arc9 請檢查目前方案有哪些必要改動。
```

正文交代判斷、理由與必要改動；詳細分析與可選改善放在附錄。預設依請求的語言回答，也可指定語言與篇幅。

也可提供 [SKILL.md](dist/skills/arc9/SKILL.md) 的完整路徑，請模型讀取並使用；須保留完整的 `arc9` 資料夾，包含其中的 `references`。

提示詞來源、封裝檢查與重建方式見[維護說明](MAINTENANCE.md)。
