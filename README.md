# arc-9

[English](README.en.md)

`$arc9` 是手動呼叫的唯讀工程審查 skill。它會沿著實際操作追查問題怎麼發生，說明方案是否需要改動、該改哪裡，以及判斷的依據。

它以「使非法狀態無法被表達」為最高原則：優先改變資料與操作的安排，讓違反需求的狀態無法建立。審查只讀取任務提供或允許讀取的材料，不修改程式、檔案、設定或外部狀態。

## 實際案例

以下是四個 CSV 匯入方案的審查摘要。

| 題目中的方案 | 審查判斷與建議 |
|---|---|
| 每週約兩次、每次最多 500 筆的 CSV 匯入，預留多格式工廠並加入佇列；舊工作可能覆寫修正資料。 | 不宜直接實作。先保留 CSV 解析、匯入服務與資料庫，量測耗時後再決定是否背景執行。先確認較晚受理優先是否符合需求；若採用，受理時配號並固定 CSV，寫入時原子拒絕舊序號。整批更新與完成狀態同交易提交，重試沿用原工作與輸入。 |
| 租戶只能匯入自己的檔案。API 檢查路徑字串的前綴，檔案服務開檔前會化簡路徑。 | `/tenants/A/../B/customers.csv` 能通過 A 的前綴檢查，開檔時卻讀到 B 的檔案；worker 再把 B 的資料匯入 A，讓 A 查詢。取消任意路徑輸入，由可信租戶身分推導固定來源路徑，並以同一來源決定寫入租戶。 |
| 每秒到達 20 個工作、完成 2 個，要求等待不超過 30 秒；提案只擴大佇列。 | 不可交付。擴大佇列沒有增加處理能力，前端重送還會放大負載。無法承擔時拒收；接受時原子保存工作與中斷後補送所需的資料，例如使用交易式 outbox。前端追蹤原工作並對重送去重。已接受工作須在期限內啟動或明確失敗，並驗證 1 秒回覆與 30 秒等待要求。 |
| 5 人內部工具以單一交易匯入 CSV；重送視為新匯入，允許舊檔再次覆寫修正資料。 | 可交付。驗證後使用固定解析結果，整批交易與唯一鍵維持資料約束。重送覆寫與同鍵衝突順序符合已確認的需求；失敗與結果未確認有明確表示。題目提供的耗時、記憶體與滿載拒收紀錄符合本期預算。 |

[完整題目與回答](examples/masters-lens/README.md)。

以下案例檢查需求或方案改變後，判斷如何跟著改變。

| 題目中的變化 | 審查判斷 |
|---|---|
| 報表 45 秒完成。任務指定 R1 的 30 秒要求，實作備註卻寫可等 60 秒；之後任務改指定 R2 的 60 秒要求。 | 依 R1 判定不符合，實作備註不能改變要求；任務指定 R2 後，改判符合。 |
| 下載與刪除都可能檢查 A 的權限、實際操作 B。先修正下載，再修正刪除。 | 兩者都未修時指出兩項問題；下載修正後只保留刪除問題；兩者修正後判定沒有仍須修正的實作缺陷，另建議補測只有讀取或只有刪除權限的身分。 |

## 使用

模型依當前問題選用方法，例如追蹤資料怎麼處理、操作卡住時還會拖住哪些工作、檢查通過後資料是否又被改動，以及中斷重試會留下什麼結果。它也會比對各層如何解讀同一輸入、核對耗時與資源用量。這些方法以九位大師的名字收錄於 [SKILL.md](dist/skills/arc9/SKILL.md)。

方案改變後，重新檢查受影響的步驟，確認仍符合本次任務指定的要求。

安裝後，在目前的任務討論中呼叫：

```text
$arc9 請檢查目前方案有哪些必要改動。
```

明確指定輸出語言時依指定回答；未指定時，跟隨使用者本次請求的主要語言與書寫形式。中文預設 250–400 個正文字元，英文預設 150–250 詞，全文最多三個條列項目，交代判斷、依據，以及影響決策的未知與必要下一步，不寫客套話或開場白。本次任務可指定其他輸出要求；計數與省略條件見 [skill 共通契約](dist/skills/arc9/SKILL.md)。

[中文請求、英文請求與指定語言覆寫的完整回答及執行紀錄](examples/masters-lens/language/README.md)。

## 安裝

[下載 ZIP](dist/arc-9.zip)，解壓縮後將 `arc9` 資料夾放入 Codex 的 skills 目錄。Windows 預設位置為 `C:\Users\<使用者名稱>\.codex\skills\`；已設定 `CODEX_HOME` 時，使用該目錄下的 `skills`。下個回合即可呼叫 `$arc9`。

也可以直接提供 [SKILL.md](dist/skills/arc9/SKILL.md) 的檔案路徑，請模型讀取並使用。
